# OnlyMLM / Nema — Установка в Bagisto и текущая интеграция

[English](setup.en.md) · [Türkçe](setup.tr.md) · [Русский](setup.ru.md) · [Français](setup.fr.md) · [Español](setup.es.md)

Документ подготовлен 23 ноября 2026 года по рабочим копиям `nema-platform` и `onlyMlmBagisto`. Продукт для продажи на площадках вроде Codester — исходный код Nema, который копируется в существующий проект Bagisto. Полное приложение Bagisto в коммерческий ZIP не входит.

Коммерческая версия Nema вроде `1.0.0` здесь не объявляется. `2.4.x-dev` также не является конкретным стабильным тегом Bagisto; совместимость с другими версиями нужно проверять отдельно.

## 2. Текущая интеграция для разработки

Сейчас проекты находятся в соседних каталогах:

```text
onlyMlm/
├── nema-platform/
│   └── packages/
│       ├── core/
│       ├── laravel/
│       └── bagisto/
└── onlyMlmBagisto/
```

Текущее подключение Nema в `onlyMlmBagisto/composer.json`:

```json
{
    "require": {
        "sryyabey/nema-bagisto": "dev-main"
    },
    "repositories": [
        {
            "type": "path",
            "url": "../nema-platform/packages/*",
            "options": {
                "symlink": true
            }
        }
    ]
}
```

Это только фрагмент, относящийся к Nema. Остальные зависимости и репозитории Bagisto сохраняются. Адаптер Bagisto зависит от Core и Laravel. Оба поставщика сервисов Nema обнаруживаются через `extra.laravel.providers` пакетов; отдельных записей Nema в текущем `bootstrap/providers.php` Bagisto нет.

Соседний каталог и символические ссылки используются для разработки. Установка для клиента копированием описана ниже. Добавление документа не преобразовало существующие репозитории в эту структуру.

## 3. Структура коммерческого ZIP

Копируйте все три пакета целиком, сохраняя внутреннюю структуру:

| Источник в nema-platform | Назначение в проекте Bagisto клиента |
| --- | --- |
| `packages/core/` | `packages/OnlyMlm/Core/` |
| `packages/laravel/` | `packages/OnlyMlm/Laravel/` |
| `packages/bagisto/` | `packages/OnlyMlm/Bagisto/` |

Структура после распаковки:

```text
OnlyMLM-Bagisto/
├── packages/
│   └── OnlyMlm/
│       ├── Core/
│       │   ├── composer.json
│       │   └── src/
│       ├── Laravel/
│       │   ├── composer.json
│       │   ├── config/
│       │   ├── database/
│       │   └── src/
│       └── Bagisto/
│           ├── composer.json
│           ├── config/
│           └── src/
├── setup.md
├── setup.en.md
├── setup.tr.md
├── setup.ru.md
├── setup.fr.md
└── setup.es.md
```

Не копируйте только `src/`: поставщики используют относительные пути к `config/`, `database/migrations/` и `src/Resources/`. Несмотря на заглавные буквы в названиях целевых каталогов, пространства имён PHP остаются `Nema\Core`, `Nema\Laravel` и `Nema\Bagisto`.

Не включайте `reference/legacy-nema`, `.git`, `.env`, резервные копии баз данных, реальные лицензионные ключи, закрытые ключи подписи, `vendor`, `node_modules` и локальные рабочие данные. Корневой `composer.json` платформы не заменяет файл `composer.json` Bagisto клиента.

## 4. Установка исходного кода в существующий Bagisto

Команда `composer require` не используется; Nema не загружается из Packagist или частного репозитория Composer. Существующий Composer в Bagisto продолжает обеспечивать автозагрузку классов. Нужен доступ к терминалу.

### 4.1. Подготовка и копирование

Нужна работающая установка Bagisto, соответствующая требованиям PHP/Laravel. Сделайте резервную копию файлов и базы, сначала проверьте процедуру в тестовой среде. Скопируйте `packages/OnlyMlm` из ZIP в каталог `packages/` Bagisto.

### 4.2. Настройка автозагрузки

Добавьте три записи в существующий объект `autoload.psr-4` корневого `composer.json` Bagisto. Сохраните записи App, Database и Webkul:

```json
{
    "Nema\\Core\\": "packages/OnlyMlm/Core/src/",
    "Nema\\Laravel\\": "packages/OnlyMlm/Laravel/src/",
    "Nema\\Bagisto\\": "packages/OnlyMlm/Bagisto/src/"
}
```

Это фрагмент для объединения, а не весь файл. Само наличие `composer.json` внутри скопированных пакетов не устанавливает зависимости и не запускает обнаружение поставщиков при ручной установке. Требования, включая версию Laravel, проверяются вручную.

### 4.3. Регистрация поставщиков сервисов

Добавьте классы в указанном порядке в конец существующего списка `return [...]` файла `bootstrap/providers.php`, после поставщиков Webkul:

```php
Nema\Laravel\Providers\NemaServiceProvider::class,
Nema\Bagisto\Providers\NemaBagistoServiceProvider::class,
```

У Core нет поставщика сервисов. Текущие модели Nema используют Laravel Eloquent; добавлять `ModuleServiceProvider` Nema в `config/concord.php` не нужно. Не совмещайте автоматически обнаруживаемую Composer-установку с ручной копией Nema. Переход с текущей локальной Composer-установки также требует миграции зависимостей и lock-файла и не входит в эти шаги новой установки.

### 4.4. Автозагрузка и база данных

Выполните в корне проекта Bagisto клиента:

```bash
composer dump-autoload
php artisan optimize:clear
php artisan nema:install --sync-customers
php artisan nema:doctor
php artisan route:list --name=nema
```

`nema:install`:

- Публикует настройки с тегами `nema-config` и `nema-bagisto-config`, не перезаписывая существующие файлы.
- Запускает Laravel `migrate`: применяются все ожидающие миграции приложения, а не только Nema.
- Создаёт таблицы Nema и атрибуты баллов товаров Bagisto через миграции.
- Синхронизирует переводы баллов товаров с существующими локалями.
- С `--sync-customers` импортирует существующих покупателей как участников Nema, не создавая автоматически спонсорские связи и позиции бинарного дерева.

В production сначала проверьте ожидающие миграции и создайте резервную копию:

```bash
php artisan nema:install --force --sync-customers
```

Если миграции уже выполнены, опубликуйте настройки и синхронизируйте участников без миграций:

```bash
php artisan nema:install --no-migrate --sync-customers
```

## 5. Настройки и лицензирование

После установки Bagisto использует `config/nema.php` и `config/nema-bagisto.php`. Исходные значения по умолчанию находятся в каталогах `config/` пакетов.

Основные переменные окружения:

```dotenv
NEMA_PLAN_VERSION=1
NEMA_CV_MAX_LEVELS=10
```

Для лицензионной поставки замените заполнители реальными значениями от продавца:

```dotenv
NEMA_LICENSE_ENABLED=true
NEMA_LICENSE_SERVER=https://onlymlm.com/api/v1/licenses
NEMA_LICENSE_KEY=YOUR-LICENSE-KEY
NEMA_LICENSE_PRODUCT=onlymlm-bagisto
NEMA_LICENSE_PUBLIC_KEY=YOUR-BASE64-PUBLIC-KEY
NEMA_LICENSE_ENVIRONMENT=production
NEMA_LICENSE_CACHE_TTL=86400
```

```bash
php artisan optimize:clear
php artisan nema:license activate
php artisan nema:license status
php artisan nema:license validate
```

В исходной конфигурации проверка лицензии по умолчанию выключена; подготовьте лицензионную политику продукта с учётом этого. При включении проверяется документ с подписью Ed25519. Клиенту передаётся только открытый ключ. Если сервер недоступен, кэшированный документ используется только в пределах подписанного срока `grace_until`. Middleware проверяет состояние лицензии и разрешённые функции; GET-доступ без действующей лицензии не открывает все функции. Экран лицензии находится в разделе Nema панели администратора.

Эти команды работают с собственным API лицензий продукта. Готовая проверка кодов покупки Codester из этого не следует. Сопоставление кода покупки с лицензионным ключом Nema нужно разработать отдельно.

## 6. Как работает интеграция с Bagisto

### Идентификация и сети

- Идентификатор tenant имеет вид `channel:{id}`, участника — `customer:{id}`.
- `customer.create.after` синхронизирует покупателя с участником Nema.
- Событие рендеринга представления добавляет поле спонсора в форму регистрации.
- `customer.registration.before` проверяет `sponsor_code` или реферальный код в сессии. Если в tenant ещё нет участников Nema, первая регистрация возможна без спонсора; последующие требуют действующего спонсора.
- `customer.registration.after` назначает проверенного спонсора, но не размещает участника автоматически в левой/правой ветви бинарного дерева.
- Реферальная ссылка имеет вид `/nema/join/{code}`.

### Заказы, баллы и пакеты

| Событие Bagisto | Действие Nema |
| --- | --- |
| `checkout.order.orderitem.save.after` | Снимок баллов позиции заказа |
| `sales.order.update-status.after` | Обработка PV/CV и квалификации пакета при подходящем статусе |
| `sales.order.cancel.after` | Сторнирование баллов и отмена пакета |
| `sales.refund.save.after` | Сторнирование возвращённых баллов |

Подходящие статусы по умолчанию: `processing` и `completed`. У товаров используются `nema_pv` и `nema_cv`. PV начисляется покупателю; CV идёт по восходящей спонсорской линии до заданной глубины. Возвраты/отмены сторнируются по исходному снимку. Миграции добавляют поля в семейства атрибутов; семейства, созданные позже, проверяются отдельно.

### Экраны, права и темы

Поставщик загружает меню администратора/клиента, ACL, маршруты, пространство имён представлений/переводов `nema-bagisto` и view composer профиля. Каталог переопределений пакета добавляется с приоритетом к пространству представлений `shop`. Ручная правка ядра Bagisto не требуется.

- Вход администратора: `/{admin_url}/nema`, где `admin_url` — `config('app.admin_url')`.
- Обзор клиента: `/customer/account/nema`.
- Сети и баллы: `/nema/mlm`, `/nema/mlm_points`, `/nema/binary`, `/nema/binary_points`.
- Карьера: `/nema/career`.

Для пользовательской темы проверьте вызов соответствующего события рендеринга в форме регистрации и совместимость клиентских экранов с переопределениями пакета. Выдайте ACL-права Nema ограниченным административным ролям. Установка не меняет существующие assets Bagisto; само копирование исходников не требует сборки frontend.

### Финансовый функционал

Nema формирует результаты сети, баллов, пакетов, карьеры и периодических бинарных расчётов. `nema.features.income` сейчас равно `false`. Кошелёк, денежные переводы, выплаты комиссий и бухгалтерская система не устанавливаются. Для финансовых интеграций используйте постоянный outbox `nema_domain_events` и контракт обработки событий из README. Коммерческое описание должно соответствовать этому объёму функций.

## 7. Проверка установки и устранение неполадок

`nema:doctor` проверяет основные настройки и таблицы, но не все сквозные сценарии. В тестовой среде проверьте:

1. Меню открываются, а неавторизованные пользователи не получают доступ к данным других участников.
2. Для существующих клиентов созданы участники Nema; повторная синхронизация не создаёт дубликатов.
3. Работают первая регистрация, регистрация со спонсором и реферальные ссылки.
4. Поля PV/CV видны, подходящие заказы создают баллы, повторные события их не дублируют.
5. Частичные возвраты и отмены создают правильные сторнирующие записи.
6. Бинарное размещение, пакеты и карьеры соблюдают границы tenant.
7. Корректно обрабатываются действующие/недействующие лицензии и права на функции.

Базовая проверка production:

```bash
php artisan nema:doctor --production
```

Она ожидает `APP_ENV=production`, `APP_DEBUG=false`, HTTPS в `APP_URL` и подключение очереди, отличное от `sync`. При использовании очередей управляйте worker-процессами согласно схеме развёртывания.

| Симптом | Что проверить |
| --- | --- |
| `Class Nema... not found` | Три пути PSR-4, регистр каталогов и `composer dump-autoload` |
| Нет Artisan-команд `nema` | Порядок поставщиков и записи в `bootstrap/providers.php` |
| Нет таблиц Nema | Вывод миграций и подключение к нужной базе |
| Нет меню или настроек | `optimize:clear`, ACL, опубликованные настройки и функции лицензии |
| Ошибка спонсора при регистрации | Действующий код того же tenant и состояние существующих участников |
| Баллы не начисляются | Сопоставление клиента, PV/CV товара, статус и поток событий |
| Нет функции Sodium | Расширение Sodium в PHP, выполняющем проверку лицензии |

## 8. Обновления и готовность к продаже

Сделайте резервные копии файлов/базы, обновите все три каталога вместе, перестройте автозагрузку, очистите кэши и проверьте ожидающие миграции. Установщик не перезаписывает опубликованные настройки; переносите новые значения по умолчанию после проверки. При включённом лицензировании повторно проверьте лицензию.

## 9. Демонстрационные данные (необязательно)

После установки Bagisto и Nema выполните из корня Bagisto для демонстрационной базы:

```bash
php artisan nema:demo-seed --with-products --with-careers --force
```

Создаёт 35 клиентов, спонсорскую/бинарную сеть, 70 тестовых записей PV/CV, пять карьер и 25 товаров с изображениями и PV/CV. Названия по умолчанию на английском. Повторный запуск переводит исходные турецкие имена клиентов/карьер, сохраняя пароли, баллы и изменённые вручную имена. Команда товаров обновляет содержимое и остатки по SKU; используйте только демокаталог.

Email лидера выводится в терминале (канал ID 1: demo.c1.member1@example.test). Пароль выводится только при первом создании; существующие пароли сохраняются. Заказы, платежи и назначения пакетов не создаются.

При нескольких каналах вместо общей команды используйте команду с кодом канала ниже. Товары добавляются отдельно в первый канал; проверьте целевой канал.

```bash
php artisan nema:demo-seed --channel=default --with-careers --force
php artisan nema:demo-products add
```
